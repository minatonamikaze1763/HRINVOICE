## 2. Features we should include

A. Search and filters

- Search by invoice number, customer name, mobile number, chassis number or engine number.
- Filter by invoice date, standard vehicle/EV and document availability.
- Sort newest or oldest first.
- Show a clear “No invoices found” message.
- Support partial matches and ignore letter case where appropriate.

B. View invoice details Open an individual record in a dedicated details view.

- Customer and contact details
- Invoice number, date and vehicle information
- Chassis and engine numbers
- Payment or hypothecation details
- Ex-showroom price, GST breakdown and insurance IDV
- Document-generation status
- View or print the invoice PDF

C. Download previously generated documents

Each invoice should have separate actions:

- Download Invoice PDF
- Download Form 22 PDF
- Download Complete ZIP

If a saved PDF is missing, clearly indicate that it needs to be regenerated from the saved details or restored from a backup.

D. Reopen and correct an invoice

- Load saved invoice details into the existing form.
- Let the user correct details and regenerate documents.
- Preserve the original record or track that a revision was made.
- Warn before overwriting any saved document.
- Keep the duplicate invoice-number check active.

E. Record management

- Export invoice records for backup.
- Import a backup and detect duplicate records.
- Delete a record only after confirmation.
- Optionally select multiple invoices for bulk ZIP downloads or backup.
- Display the number of saved records and the last backup date.

## 4. How should the documents be stored?

For your browser-based app, I recommend this approach:



JSON backup — portability

Export records and relevant document files or package them into a backup ZIP, then restore them later.

Important limitation

Browser data can be lost if site data is cleared or the browser profile changes. A backup is essential. Local records are not automatically shared across computers.

Important: Saving only the invoice details is enough to regenerate PDFs, but it is not the same as preserving the exact originally generated files. If you want to download the original documents later, store the generated PDFs/ZIP as well.

Search → View → Download → Reopen / Regenerate

## 6. Implementation order

1. Build the invoice register and save records whenever document generation succeeds.
2. Add search, sorting and filters.
3. Add view details and download actions for the saved PDFs/ZIP.
4. Add reopen/edit and safe regeneration.
5. Add backup and restore.
6. Add bulk operations and optional date/vehicle filters.

My recommendation: keep Invoice Register as its own page, with a button in the main header beside Settings. Keep the current draft autosave separate from the permanent invoice history, and don't treat an invoice as successfully generated until the document-generation process actually succeeds.
